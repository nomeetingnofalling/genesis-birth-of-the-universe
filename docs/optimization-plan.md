# Birth: ускорение до 30 fps при «плотности точек» = 100

Цель: стабильные 30 fps на MacBook Pro 13" 2019 (Core i5) при плотности 100 (5200 точек).
Ветка `multicore`. Даты: анализ и внедрение 2026-09-24.

## Что тормозило (замер до изменений)

Headless Chromium, облачный CPU без видеокарты, 5200 точек, остальные ползунки по умолчанию.

| этап | мс/кадр |
|---|---|
| весь кадр (JS) | ~80–100 (для 30 fps нужно меньше 33, лучше не больше 25) |
| drawDots: отрисовка точек | ~71–90 (≈ 88 %) |
| · свечение (drawImage × 5200) | ~34 |
| · шлейф (stroke + strokeWeight + line × 5200) | ~22 |
| · ядро (fill + circle × 5200) | ~16 |
| resolveCollisions | 4.2 |
| drawStars | 3–5 |
| updateWordPoints (вся физика) | 1.4 |
| drawLinks при «количество линий» = 100 | +17 |

Вывод: тормозит не расчёт (~6 мс), а около 15 600 отдельных вызовов Canvas 2D через p5 за кадр.
Канвас 2D не раскладывается по ядрам процессора.

## Что сделано в ветке multicore

1. **WebGL-слой для точек и линий связи.** Прозрачная WebGL-канва поверх p5-канвы.
   Каждая точка превращается в три фигуры (шлейф, свечение, ядро), линия связи — в ещё одну;
   всё уходит в один буфер и рисуется одним вызовом `drawArraysInstanced` в том же порядке, что раньше
   (линии под точками, для каждой точки шлейф → свечение → ядро). Профиль свечения в шейдере
   совпадает со спрайтами (1 → 0.48 → 0), у шлейфа и линий круглые концы, как у `line()` в p5.
   Если WebGL или расширение `ANGLE_instanced_arrays` недоступны, работает прежний путь `drawDots2D`
   (в консоли будет предупреждение, в углу экрана `2D` вместо `GL`).
2. **Столкновения и поиск соседей для линий** на сетке из `Int32Array` (сортировка подсчётом):
   без `Map` и новых массивов на каждом кадре, порядок обхода прежний. Физика совпадает
   с исходной версией бит в бит (проверено на 150 кадрах с одинаковыми часами).
3. **Звёзды:** цвета считаются арифметикой вместо ~8 объектов `p5.Color` на звезду;
   тень и блик вдоль хвоста рисуются только у звёзд толщиной от 1 px;
   звёзды целиком за краем холста пропускаются.
4. **Чёткость:** p5-канва всегда в x1. Автомасштаб теперь меняет только чёткость слоя точек
   (до плотности пикселей экрана, на Retina до x2) и смотрит на средний FPS за секунду,
   а не на мгновенный `frameRate()`. Качели 30↔20 fps ушли.

## Результат (тот же стенд, время JS на кадр)

| сценарий | было | стало |
|---|---|---|
| плотность 100, остальное по умолчанию | 100.8 мс | **7.0 мс** |
| плотность 100 + линии 100 | 119.0 мс | **16.9 мс** |
| все ползунки визуализации на максимуме | 177.6 мс | **12.3 мс** |

Отрисовку на видеокарте в облаке замерить нельзя (там нет GPU). На Mac её стоимость для
~16 тыс. маленьких фигур ожидается в пределах 1–2 мс; проверять по счётчику в правом верхнем
углу (`FPS … · x… · GL`).

Сверка картинки: положение всех точек совпадает; средняя разница пикселей 1.2 из 255.
Свечение в GL-версии на несколько процентов ярче, чем в программной отрисовке облачного
браузера: тот при малой прозрачности округляет вниз. На Mac с аппаратной отрисовкой
разница должна быть меньше.

## Что дальше (по желанию)

- Поиск соседей для линий (~9 мс при «линиях» = 100) можно ускорить ещё, если это понадобится.
- Больше 5200 точек: физику перенести в `Float32Array`, затем в Web Worker(ы) (Blob-URL, чтобы
  открывалось двойным кликом) или в шейдеры.
- Форк `switch/index.html` пока на старой отрисовке. Его можно перевести так же.
- Буква «А» во вступлении не грузится: base64 в `TIGLE_GLYPH_DATA_URI` обрезан («...»).
  Целая версия есть в `green/index-meetya-2.html`.

## Про Web Workers (исходная идея ветки)

Воркеры ускоряют только расчёт, а это ~7 % кадра. При этом теряются столкновения между точками
разных воркеров, а `new Worker('file.js')` не работает при открытии файла двойным кликом (file://).
Поэтому в этой ветке сначала сделана отрисовка на видеокарте, а воркеры отложены до момента,
когда точек станет в разы больше.

Первый прототип WebGL-слоя (до внедрения): `docs/webgl-points-prototype.js`.
