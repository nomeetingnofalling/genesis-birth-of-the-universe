# AGENTS.md — контекст для агента

Ты работаешь в приложении Codex с папкой художника (курс «Введение в цифровое
искусство и вайб-кодинг»). Хозяин папки — не программист: он пишет просьбы
словами и смотрит результат в браузере. Твоя задача — превращать его просьбы
в живую картинку, ничего не спрашивая о технике.

## Что в папке

- `слова.txt` — материал: по одному слову или короткой фразе на строку. Это
  «коробка» художника, источник всего, что появляется на экране.
- `index.html` — единственный файл работы. Если его нет — создай. Открывается
  двойным кликом в браузере, без сервера и установки.
- `green/` — копии `index.html`, которые точно работали. Не трогай.

## Как устроена работа

- Всё в одном файле `index.html`: разметка, стили и код внутри. Библиотека —
  p5.js с CDN: https://cdnjs.cloudflare.com/ajax/libs/p5.js/1.11.13/p5.min.js
  Других внешних файлов, шрифтов и картинок из интернета не подключать.
- Канвас 1280×720, 30 кадров в секунду, растягивается на окно с сохранением
  пропорций. Фон тёмный `#0e0f12`.
- Палитра, только она: светлый `#e6e8ee`, приглушённый `#8a8f99`,
  оранжевый акцент `#ff7a50`, голубой акцент `#5aa9ff`.
- Слова читаются из `слова.txt` через `loadStrings` в `preload()`. Если файл
  не открылся (браузер запретил чтение с диска) — используй те же слова,
  вписанные в код запасным списком, и обнови этот список при каждой правке.
- Случайность только сидированная: `randomSeed(7)` и `noiseSeed(7)` в
  `setup()`. Тот же файл — та же картинка. `Math.random()` не использовать.
- Показ идёт через Zoom: формы крупные, движение медленное. Частицы не
  меньше 3 px, текст не меньше 30 px, за один кадр ничто не сдвигается больше
  собственного размера. Мелкое и быстрое в Zoom пропадает.
- Свечение и следы — мягкие: полупрозрачный фон вместо clear, режим
  наложения `ADD` или `lighter` с малой альфой. Картинка должна быть одинаково
  яркой при любых настройках — не темнеть и не выгорать в белое.
- Если просят «контрол», «ползунок», «ручку» — обычный `<input type="range">`
  внизу страницы с подписью, значение читается прямо в `draw()`, картинка
  меняется сразу, без перезагрузки. Крайние положения должны выглядеть
  осмысленно: на нуле — исходное состояние, на максимуме — предельное.
- Держи ≥ 25 fps на обычном ноутбуке. Если частиц слишком много — уменьшай
  их число, а не размер.

## Правила

1. Меняй только то, о чём просят. Остальное оставляй как было.
2. Один запрос — одна правка. Не переписывай файл целиком без нужды.
3. Стиль — современный медиа-арт: точки, линии, воздух, движение. Без рамок,
   кнопок и «учебных» фигур; без текста-подсказок на экране, кроме подписей
   контролов.
4. Не создавай новых файлов и не удаляй существующие; git не используй.
5. Не спрашивай разрешения на технические решения — принимай их сам в рамках
   этого файла. Спрашивай только, если просьба противоречит самой себе.
6. После правки ответь двумя строками, простыми словами, без терминов: что
   теперь видно на экране и что нужно сделать, чтобы это увидеть (обновить
   страницу в браузере).
